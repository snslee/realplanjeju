## §6 이 세션에서 얻은 재사용 교훈 8건

| # | 교훈 |
|---|---|
| 1 | **화면 편집의 기준 파일은 반드시 `origin/main`에서 새로 받는다.** D드라이브·이전 대화 파일 기준으로 세 번 사고 났다 |
| 2 | **배열을 수정하면서 인덱스를 원본에서 찾지 않는다.** 매번 수정본에서 다시 찾는다. `</body>`는 `max(...)`로 마지막 것 |
| 3 | **런타임 생성 패널은 `switchTab` 전에 만들어야 한다.** 순서가 뒤면 null로 터져 뒤 문장이 안 돈다 |
| 4 | **게이트는 구문·회귀만 본다. 「눌러서 뜨는가」는 실화면으로만 잡힌다.** 배포 후 실클릭까지 한다 |
| 5 | **RPC가 jsonb로 `ok:false`를 주면 예외가 아니라 정상 응답이다.** `r.error`만 보면 실패를 성공으로 보고한다 |
| 6 | **테이블에 행이 있다 ≠ 화면에서 보인다.** 화면 배선 전 **RLS SELECT 정책**을 먼저 본다 |
| 7 | **값을 바꾸기 전에 그 값을 하드코딩한 객체를 찾는다.** 함수·뷰 정의를 정규식으로 훑는다 |
| 8 | **다른 방이 동시에 DB를 쓴다.** 남의 `in_progress` 행은 건드리지 않는다. 통제는 **막지 말고 보이게** 한다(CHECK/FK보다 감시 뷰) |
